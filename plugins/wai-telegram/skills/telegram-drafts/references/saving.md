# Сохранение и актуализация черновиков

## Подготовить или обновить ответ

«Что ответить» означает текст в текущем разговоре с агентом. «Сделай драфты всем непрочитанным» или «сохрани черновики в Telegram» разрешает `save_draft`; «обнови/приведи в порядок устаревшие черновики» разрешает исправление или очистку подтверждённо устаревших черновиков в указанном охвате. «Проверь» и анализ входящих сами по себе не разрешают запись. Если отправка уже явно поручена, не запрашивай повторного подтверждения того же действия; соблюдай выбранного адресата, содержание и объём.

Пиши кратко, естественно, на языке конкретной переписки. Сохраняй заданный пользователем текст, если он просит точную формулировку. Не обещай время встречи, оплату, приём на работу, скидку или выполненную работу без основания. Для HR/CRM учитывай актуальные правила задачи и живой статус в соответствующем источнике, когда от него зависит ответ; недоступный Notion нельзя заменить старым снимком и назвать это сверкой.

Перед записью пакета прочитай существующие черновики через `list_drafts` и актуальное продолжение выбранных переписок. Один снимок черновиков можно использовать для небольшого пакета, а не запрашивать весь список для каждого чата. `save_draft` заменяет весь черновик: сохрани полезное пользовательское содержание; не затирай его несвязанным шаблоном. Если существующий текст уже подходит, не перезаписывай его. Черновик с неизвестным `chat_id` нельзя надёжно сопоставить получателю; не угадывай.

`save_draft` сохраняет текст. Фото и документы в облачном черновике не поддерживаются, как и `reply_to_message_id`, темы форума и метаданные форматирования. Не перезаписывай черновик, если нужно сохранить неподдерживаемую привязку или оформление; покажи предложенный текст отдельно. Если уже отправленный ответ полностью закрывает смысл старого черновика и очистка входит в поручение, используй `clear_draft`. Если в черновике остался другой открытый вопрос, сохрани его. Непонятный случай покажи пользователю, продолжив обработку остальных чатов.

Сохраняй по одному черновику на чат, без массового параллельного запуска записей. Проверь `saved: true` и `sent: false` для успешного сохранения; для очистки — `cleared: true`, `sent: false` и пустоту. После пакета сверяй изменённые черновики через `list_drafts`: идентификатор, текст и отсутствие очищенного черновика. При изменении разговора или ручной правке за время обработки перечитай его; не переписывай поверх нового состояния. Сервер не предоставляет условной записи черновика, поэтому повторная проверка уменьшает риск гонки, но не делает операцию атомарной.

При обрыве связи сначала прочитай текущий черновик: запись могла состояться. Если текст совпадает с задуманным, повтор не нужен. Если результат нельзя установить, отметь неопределённость; не повторяй весь пакет. При ограничении Telegram соблюдай указанное время ожидания, при потере авторизации останови записи до восстановления доступа. Уже проверенные успешные результаты сохрани в отчёте.

Сохранение черновиков не разрешает отправлять их через `send_message`, `reply_to_message` или `send_file`. Если пользователь отдельно попросил прислать сводку себе в Избранное, используй `telegram-save` для этой сводки. При неопределённом результате отправки сначала проверь историю: автоматический повтор может создать дубль. Удалённый аккаунт или явный запрет доступа — причина закончить попытки для этого чата и указать ограничение.


## Пост с картинкой без Computer Use

Облачный черновик Telegram хранит только текст. Для полного поста Wai Telegram имеет собственное хранилище: одна JPEG/PNG-картинка до 10 MiB, Markdown-подпись до 1024 UTF-16 символов и проверенный UUID адресата. Сохранение не вызывает Telegram, не отправляет файл в Избранное и не создаёт отложенное сообщение. Доступ: `read,draft`; публикация отдельно требует `write`.

Если пост будет публиковать AI, включи в подпись приписку по [правилу telegram-send](../../telegram-send/SKILL.md#приписка-об-ai) до сохранения и покажи её в предпросмотре. Лимит 1024 UTF-16 символа учитывает и приписку. Обычный текстовый черновик для ручной отправки этого не требует.

Перед записью выбери новый UUID и сохрани его в рабочем артефакте. При обрыве используй тот же ID и те же файлы: запись идемпотентна. Изменённая версия получает новый ID, чтобы approve всегда относился к неизменному посту.

```sh
python3 scripts/post_draft.py save --id NEW_DRAFT_UUID --chat-id VERIFIED_CHAT_UUID --file /absolute/path/chart.jpg --caption-file /absolute/path/post.md --receipt /absolute/path/server-draft.json
```

Скрипт использует `TELEGRAM_AI_KEY` из безопасного окружения и `TELEGRAM_AI_URL` (по умолчанию `https://telegram.waiwai.is`). Проверяет сохранённую подпись, адресата и точные байты изображения через API. Успешный результат: `storage: wai_telegram`, `status: draft`, `sent: false`, `readback_verified: true`. Это означает «полный черновик сохранён в Wai Telegram», а не «фото прикреплено к черновику в приложении Telegram». Покажи текст и изображение вместе.

```sh
python3 scripts/post_draft.py read --id DRAFT_UUID
```

После явного поручения пользователя опубликовать именно этот пост в указанном канале перечитай ID, статус, адресата и содержание. Проверь приписку по правилу `telegram-send`. Только для `status: draft`: если приписки нет, подготовь новую версию с новым ID и покажи итоговую подпись; исходное поручение опубликовать действует и для добавления стандартной приписки. Если пользователь явно потребовал неизменный текст, соблюдай это исключение. Сохранённый ID не меняй и не публикуй обе версии. Для выбранной версии используй отдельную команду:

```sh
python3 scripts/post_draft.py publish --id APPROVED_DRAFT_UUID --approve
```

Обычная просьба сохранить черновик не разрешает эту команду. `published` с `telegram_message_id` означает подтверждённую отправку; проверь это сообщение и приписку, если она предусмотрена, через `get_chat_messages`/`get_message`. Уже опубликованный пост не отправляй заново ради приписки. `publishing` или `unknown` означает неопределённый исход, не повторяй отправку и не создавай новый ID для обхода: сначала прочитай историю адресата. Повтор публикации уже отправленного ID возвращает прежний результат без повторной отправки.

Если API недоступен, оставь материалы локально через `prepare_post_draft.py` и явно назови результат локальным. Старый `save_draft_file.py` остаётся несовместимым с Telegram и не используется. Никакого автоматического перехода к Computer Use.
